Read answers from the top, tag the checks, restart without the hassle

Four changes to the chat screen. Answers no longer drag you to the bottom while they’re written. Typing #artifact switches that checklist item on. After Restart Workbench, an open tab picks up the new version by itself. And the top bar no longer repeats that the agent is working.

Status: committed locally as f621a55, not pushed. Each change was tried in a private copy of Workbench, driven in a hidden Chrome window, and the type check and related tests pass. Your own Workbench shows them after one Restart Workbench plus one Cmd+R.

What changed

Grouped by what you see on screen. The drawings are mock-ups, not screenshots.

01Answers stay where they start

Before: while an answer was being written, the chat kept scrolling to its newest line. You ended up reading from the bottom up, or chasing the text.

Now, after you send a message, the view moves down only until your message reaches the top of the screen, then stops. The answer writes in below it, so you read it from its first line. Opening a chat lands the same way: on your last message, with its answer below.

  • Settings → General → Reading → Auto-scroll answers brings back the old behaviour: follow the answer to its end. It is off by default.
  • In both modes, scrolling yourself stops the view from moving.

02#tags switch checklist items on

The checklist is the Checks chip under the message box: extra things the agent should do before it finishes, like run the E2E tests or commit. Before, you had to open the chip and tick them.

Now type the item’s name with a # in your message: #artifact, #e2e, #docs, #commit, #soft-fact, or a custom check’s name (“Run lint” is #runlint). Capitals, spaces and dashes don’t matter.

  • The check switches on when you type a space after the tag, or when you press Enter if the tag is last.
  • Your text stays as you typed it. An earlier version took the tag out of the text; that felt odd, so it was changed back.
  • If you switch a check off by hand, the tag still in your text doesn’t switch it back on. Only typing a new tag does.
  • Other hashes are just text: #123, #fff, ## Heading.

03The tab reloads itself after Restart

Before: Settings → System → Restart Workbench rebuilt the page and restarted the server, and that part always worked. But the open browser tab kept running the old page. You didn’t see the changes, and some parts broke, because the files the old page loads were replaced. Stopping Workbench, closing the tab and opening it again was the workaround.

Now the server tells the page which build it serves. When that changes after a restart, the tab reloads itself once and opens the same chat. Unsent text in every chat’s message box is kept across the reload. Attached files are not, because a browser can’t keep them through a reload.

Only the background service (production mode) does this. pnpm dev already reloads on its own.

server/index.ts (sends the build), shared/protocol.ts, web/src/App.tsx (compares and reloads).

The pill now appears only as Waiting for you: when the agent asks a question or needs approval for an edit. That one asks you to act.

How to test

In your own Workbench. First get the new version on screen: press Settings → System → Restart Workbench, and when it is back, press Cmd+R once. That one manual reload is needed because the tab you have open is from before change 03. After this, restarts reload the tab by themselves.

  1. Answers stay at their start. In a chat with some history, ask for something long, e.g. “explain this repo’s folders in detail”. Your message settles at the top of the screen and the answer writes in below it; the view doesn’t follow the answer down.
  2. Auto-scroll on. Settings → General → Reading → switch on Auto-scroll answers, ask again. The view follows the answer to its end. Scroll up during it: it stops following.
  3. #tags. In a new chat type fix the header #artifact (with the space). The Checks chip shows Artifact on, and the text stays as you typed it. Untick Artifact in the chip, keep typing: it stays off. End with #e2e and press Enter: the message is sent with an E2E tests chip under it.
  4. Reload after Restart. Type something in a chat without sending it, then Settings → System → Restart Workbench. When it is back, the tab reloads on its own, opens the same chat and the text is still in the box.
  5. Top bar. Send any message. No “is working” pill at the top. In Ask mode, when the agent wants to edit a file, “Waiting for you” appears.
