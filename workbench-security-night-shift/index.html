Security and robustness

01Your login and chats moved out of agents’ reach

Before: Workbench kept its data folder (the login token, every chat, settings) in workbench/data/, inside the repository. When you used Workbench to work on Workbench, an agent could read the token there without asking. With the token, a script can do anything the page can: approve its own permission cards, or start a “custom” server command, which runs any shell command.

Now the data lives in ~/.workbench, outside every project. The old folder moves there by itself on the first start, unless another Workbench is still using it; a MOVED.txt note stays behind. Each Claude process also gets deny rules, Claude Code’s own “never allowed” list: it can’t read the token, chats, settings or Soft-fact records, and can’t write anything in that folder. Attachments stay readable, because the agent gets them by path.

Checked with the real claude CLI: without the rule it read a test file, with the rule it refused. server/config.ts, server/claude.ts, scripts/service.mjs.

02Secrets are hidden in saved chats

Before: every tool output was stored word for word. If an agent ran cat .env, the keys stayed in the chat file and turned up in search.

Now values that look like secrets are replaced by their prefix and ••• in everything a chat keeps: tool output, commands, approval previews, titles and your own messages. That covers provider keys (ghp_, sk-ant-, AKIA…), private key blocks, login tokens (JWTs), Authorization headers, passwords in URLs, and SECRET=/TOKEN=/PASSWORD= style settings. The agent still gets exactly what was sent. Chats saved before this are cleaned the first time they load.

03One-time login links, and Sign out everywhere

Before: the Workbench app had the login link, token included, baked into it. Every time it opened Workbench, that link went into the browser’s history, and the token never changed.

Now the app and pnpm service open ask the running server for a one-time code. It works once and expires after 2 minutes, so only a dead code reaches the history. Settings → System → Sign out everywhere makes a new token: every other browser and old link stops working, and the page you clicked it in stays signed in.

04Keep chats, and no leftovers

In the same section, Keep chats can delete chats you haven’t used for 1 year, 90 or 30 days, with their attachments and screenshots. It never deletes a chat that’s working or whose worktree isn’t merged yet. It is Forever by default, so nothing changes until you pick something. Files left behind by deleted chats are always cleaned up, once a day.

05Restart checks the new code first

Before: Restart Workbench rebuilt only the page, then exited and let launchd (the macOS service starter) run the server code as it was on disk. A syntax error left by an agent meant a crash every 10 seconds, and no Workbench to fix it from.

Now Restart, and pnpm service restart, first run the type checker. Then they start a test copy of the new code, with an empty data folder and no agents, and it must answer within 40 seconds. If either fails, the running Workbench stays as it was and shows why. It takes about 5 seconds.

Tried on a throwaway copy of the repo: a type error and a crash on start were both caught. scripts/check-boot.mjs.

06Safer note writes, cheap tests on GitHub, newer packages wait a day

  • Reminders.md: Done and Snooze now write the whole note or nothing, through a hidden temp file that Obsidian ignores. The note keeps its permissions and its symlink. If an edit synced in from your phone while it was writing, it starts again from the new text.
  • A test workflow (.github/workflows/test.yml) runs the type check and tests on pushes to main and on pull requests. To keep cost low, it uses a Linux runner (macOS minutes count 10× on private repos), skips docs-only changes, cancels a run when a newer push arrives, and stops after 10 minutes.
  • Who pays: this repository belongs to your personal account miltonmannarino (checked with GitHub’s API), so its minutes come from your own allowance, never Lumoview’s. It has had no runs yet.
  • pnpm no longer installs package versions published less than a day ago (minimumReleaseAge: 1440), because most malicious releases are pulled within hours.

New: ⌘K palette

07One box for everything

Press ⌘K anywhere and type a few letters, in order, gaps allowed: “nsh” finds Night shift. It jumps to any chat (newest first, with what each is doing), starts a new chat in any folder, or runs an action: Run, Changes, CI, Pages, view modes, Settings, Work Hub. When the open chat waits on an approval, its three answers come first, including Allow for this chat, which had no shortcut before. Enter and Esc already answer an approval when you aren’t typing.

New: Night shift

08Queue it tonight, read the report tomorrow

Open Night shift at the bottom of the sidebar (or from ⌘K). Add requests: a folder, what to do, Claude or Codex, Auto or Accept edits, and an optional check command such as pnpm test. Then start it now, at a time, or when Claude’s 5-hour window resets, so a full allowance is there.

  • Tasks run one at a time, each as a chat in a new worktree (its own copy of the repo on a new branch), so your checkout stays as it is. The agent is told nobody can answer tonight: decide, list the choices, commit in the worktree, never push.
  • A task that waits on an approval or a question for 10 minutes is stopped and marked needs you. One still running after an hour is stopped. A usage limit pauses the shift until the window resets, then the same chat carries on.
  • The panel is the morning report: what finished, how long it took, commits not merged yet, and the check result with its output, plus Merge and Open chat for each.
  • While it runs, caffeinate keeps the Mac from idle-sleeping. A closed lid on battery still sleeps.

New: CI auto-fix

09A failed build goes back to the chat that pushed it

Turn on Fix CI failures in the CI tab, once per repository. From then on, when a chat there pushes (the agent itself, or Commit & sync), Workbench checks GitHub every 30 seconds for that commit’s results. No AI runs while it waits. If the checks fail, the failing step of up to two jobs goes back to the same chat as a message: find the cause, fix it, check locally, commit and push. That push is watched the same way. After two fixes in a row, a note hands over to you. Notes in the chat say what it’s doing, for example “Watching CI for a1b2c3d…” or “CI passed after 1 fix”.

It never spends an organisation’s CI minutes. Each fix costs one agent turn and one more CI run, so the switch is refused for any repository an organisation owns, such as Lumoview’s. There, Send to chat on a failed job hands the failure over by hand, asking for a fix and a commit but no push.

How to test

In your own Workbench, after Settings → System → Restart Workbench.

  1. Restart and check the move. Restart Workbench. You should see the toast “Checking the new code…”, then the restart. Afterwards your chats are all there, ~/.workbench exists, and workbench/data/ holds only MOVED.txt. Then run pnpm service app once, and open Workbench from the Dock: it should log you in.
  2. ⌘K. Press ⌘K, type part of a chat’s title, then press Enter. That chat opens. Try “zen”, “ci” and “night”.
  3. An approval from the palette. In a chat in Ask mode, ask for something that needs a command. While the card waits, press ⌘K. Allow once, Allow for this chat and Deny are at the top.
  4. Night shift, now. Sidebar → Night shift. Add one small request in a scratch repo, with the check git status, pick Now, and start. A chat named “Night shift: …” appears in a worktree, runs, and the report shows Done with the check result.
  5. CI auto-fix, refused for Lumoview. Open a Lumoview repository’s CI tab. The switch is greyed out and says why. In a personal repository it switches on.
  6. Sign out everywhere. Settings → System → Sign out everywhere, then click again to confirm. This tab reloads and stays signed in. Another browser showing Workbench drops to the login message.
