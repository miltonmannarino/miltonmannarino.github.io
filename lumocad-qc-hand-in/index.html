LumoCad QC Hand-In

When the checker or the corrector finishes their part of a quality check in LumoCad, they press Hand in. The building moves to the next step, the next person gets an email, and LumoPlan shows the step as done. This page explains how that works and what still needs a decision.

Built and tested · not released yet

Who is involved

Three people meet in this flow. The colors stay the same in every picture below.

Checker

Reviews the 3D model or the 2D plans in LumoCad, ticks the checklists and flags every problem found.

Corrector

Fixes the problems the checker flagged, then hands the building back so the checker can look again.

Coordinator

Plans the work in LumoPlan and needs to see which steps are really finished, without asking everyone every day.

One QC round, step by step

A QC round goes back and forth between checker and corrector until nothing is left to fix. Each arrow is one press of the Hand in button, and each one sends exactly one email.

In LumoCad the button only lights up when the person's part is complete: for the checker, every checklist is ticked; for the corrector, every flagged issue is resolved. The hand-in window then asks who gets the building next. LumoCad suggests someone sensible, and it never suggests the checker as their own corrector.

What one button press sets off

LumoCad, the Lumoview server and LumoPlan never talk to each other directly. They all work from the same building record, which keeps a log of every status change.

The three emails

Each email names the QC step and the building, and the building name links straight into the right QC mode in LumoCad. Before this, people got a vague "Work item assigned" email, sometimes several at once.

One action, one email. Handing in also makes the next person the building's assignee, which used to send an extra "New building assigned" email. That extra email is now skipped for QC hand-ins.

What the coordinator sees in LumoPlan

The postprocessing board already shows the plan. Since September it also shows which steps are really done. Now a hand-in in LumoCad ticks the QC step by itself.

When this happens in LumoCadLumoPlan ticks
Checker hands in with problems found✓ 3D QC
Corrector hands the building back✓ 3D QC corrections
Checker approves after a re-check✓ the re-check round (3D QC, round 2)
Checker approves on the first check✓ 3D QC

The same applies to 2D. Coordinators can still tick a step by hand, as before. If they did, their tick counts. Ticking only says "done". It never moves the planned dates; coordinators adjust the plan themselves.

Changing the checker later

Sometimes the checker has to change after QC is set up. LumoCad had this feature, but it was switched off because it broke on real buildings. It works again now.

Decisions we need

The original request left these open. Each one already has a working answer, so nothing is blocked, but the answers should be confirmed or changed.

1

What status means "corrections done, waiting for a re-check"?

For now

The building goes back to Pending 3D QC (or 2D). Emails and LumoPlan still know it's a re-check because the building just came from corrections.

Other option

A new status such as "3D QC corrections check". Clearer in lists and reports, but every tool needs updating.

Is going back to "Pending QC" fine?

2

Where does an approved 2D QC go, and who hears about it?

For now

Approved 2D goes straight to Ready for delivery and skips Room book. The existing "ready for delivery" email goes to the building's assignee, who at that point is the checker who just approved. Approved 3D moves to 2D postprocessing without an email.

Other options

Send buildings that need a room book there first. Let the checker pick the next person when approving, and email them.

Room book: always, never, or only for some buildings? Who should be told after approval?

3

Status changes made by hand look like hand-ins

For now

If someone changes the status by hand in the cloud admin screen, the same email goes out and LumoPlan ticks the step. The status log doesn't say where a change came from.

Other option

Record whether each change came from the Hand in button or from a manual edit, and only react to the button.

Fine as is? A manual change usually means the same thing.

4

Who may press which button?

For now

The Checker / Corrector switch in LumoCad is remembered per browser only. Anyone with access to the building can switch and hand in either way.

Other option

Store who the checker and corrector are on each building, and only show each person their own button.

Is trust enough for now?

5

Undoing a LumoCad tick in LumoPlan

For now

A step ticked by a LumoCad hand-in can't be un-ticked in LumoPlan. To correct a mistake, someone changes the status back in the cloud.

Other option

Let coordinators override the tick in LumoPlan.

Do coordinators need that?

Smaller points

  • LumoPlan only ticks QC rounds that are in the plan. If a building needs a second QC round that wasn't planned, that round isn't shown until a coordinator adds it.
  • Rounds after a client revision aren't ticked automatically yet. Coordinators tick those by hand.

Before it goes live

  1. Full test run on the test system: set up QC, hand in with problems, hand back, approve, change the checker. Check every email and the LumoPlan board.

  2. Release the Lumoview server first. It carries the emails and the new "change checker" handling. If LumoCad were released first, changing the checker would fail.

  3. Release LumoCad and LumoPlan. The Hand in buttons go live and LumoPlan starts ticking QC steps.

  4. Tell the team how the round works now and which email to expect at each step.
