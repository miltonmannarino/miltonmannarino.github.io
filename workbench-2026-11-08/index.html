What changed

Grouped by what you see on screen. The drawings are mock-ups, not screenshots. File names are where the code lives, for whoever reviews it.

01Hand a chat to another agent

Before: a chat belonged to one agent for good. When Claude hit its usage limit (the cap on how much you can use in a time window), the chat sat there until the window reset.

Relay moves a chat to another agent without starting over. Click the agent chip under the message box, pick an agent that is ready, its model and effort, and optionally what it should do next. The chat stays one chat, in the same folder and worktree. The thread shows “Handed over from Claude to Codex”.

The new agent has no memory of the old one, so Workbench gives it a brief, written without any model call: your last 8 messages, how the last turn ended, the last 12 tool steps, the last answer, and the commits and changed files since the chat began. The brief rides along with the first message and is not shown in the thread.

  • Usage limits. A chat that hits a limit now says “Usage limit · retry …” in the top bar and resumes in the same chat when the window resets. The arrow button next to that text hands the chat over instead, and cancels the wait.
  • Also under ⌘+K → “Hand this chat to another agent…”. Only an idle chat can be handed over.

02The browser extension

Describing “the blue button on the right” to an agent is slow and often wrong. The Workbench picker is a small Chrome-style extension (it also loads in Brave and Edge) that sends the agent what you are looking at. It went from 0.1.0 to 0.2.0 this week and does four things.

  • Pick an element (Alt+Shift+P, then click). The chat gets the file and line where it was written, the components around it, a CSS selector, its HTML and two screenshots. A small box asks what should change: Enter puts it in the message box, ⌘+Enter also sends it.
  • Send what’s broken (Alt+Shift+E). Console errors, uncaught errors, failed files and failed requests, with the app file and line. Never headers or request bodies. Nothing leaves the page until you press it.
  • Record a repro (Alt+Shift+R, again to stop). Your clicks, typing (password and card fields always hidden), page changes and errors, in order, with a storyboard of up to 12 pictures.
  • Show on the running page. A live link to Workbench adds an eye button on each changed file in the Changes panel. It brings your running page forward and outlines every element written in that file.

03Every server, and a way to stop it

Before: the Server tab only knew servers started by its own ▶ Run button, in the open folder, and forgot them when Workbench restarted. A server started by an agent, from a terminal, or left behind by a closed chat kept its port with no way to see or stop it.

The tab now has Other servers on this computer: every program listening on a port that was started from your home folder, a temp folder or a project. Each row shows the port (a link), the command, the folder and how long it has run. No owner means whatever started it has exited, so nothing else will stop it. Stop asks for a second click, then ends the program and whatever it started.

  • It looks only while the tab is on screen, every 5 seconds, with lsof and ps. No model call.
  • When Workbench stops it waits for its servers to exit (a forced kill after 5 seconds). It also remembers them in running.json, so one that outlived a crashed Workbench is ended at the next start. The start time is checked first, so a reused process number is never touched.
  • Removing a worktree with its chat ends whatever still runs in that folder.

04Night shift and Actions

Night shift queues tasks for agents to run unattended, each in its own worktree (a separate copy of the project folder on its own branch), with a morning report. Actions are one-click jobs a skill offers for the open folder.

  • Only if this fails. A task can carry a command that runs first. If it passes, no agent starts (no usage spent), the task reads “All clear” and the empty worktree is removed. If it fails, the output goes to the agent as “What the check found”.
  • Repeat: Every week. A task with a weekday and time queues a copy when it is due and moves on a week.
  • Usage limits. A limit pauses the shift until the window resets; then the same chat carries on, and Night shift no longer restarts the task.
  • Actions tab in the right panel (or ⌘+K → Show actions): jobs that run a command, start an agent chat, or fill in a Night shift task. The auto-heal skill offers its weekly health check here.
  • Also from 3 November: a code tree and file focus view in the right panel, the Panda theme, and Claude login, which opens your own Terminal at the project and runs the Claude CLI’s official login. Workbench never sees the token.

06Work Hub prepares the sync

Work Hub is the planning app next to Workbench (the “Work Hub” tab top left). It now serves a three-person team with a 20-minute daily sync. There is one continuous key result, “Agentic modeling” (no deadline, never behind); the streams under it (Marvin, Calvin, golden set and so on) are topics, not key results. The Obsidian notes vault is the source of truth; Notion is only a mirror.

  • Meetings become items. Pasted or vault notes are analysed into decisions, actions (owner, due date, open or done), open questions, new facts and what changed since the last meeting. Each item has a topic, free tags and a confirmed flag, because transcripts often blame the wrong person. A correction is written back into the note and kept when a note is analysed again.
  • Topic pages are built from those items without Claude, into Topics/ in the vault: current decisions (newest wins, older ones struck through), open questions, gaps, owners with their open actions, facts. Every line links to its place in the meeting note.
  • Sync prep replaces Next up as the home screen: per person, what they said they would do, what is still open, what got done; the new decisions; open questions; where the notes disagree with the repos; and a branch map. “Prepare the sync” in the chat hands Claude the same prep.
  • Notion mirror. Review gets a new proposal, kr_update: a decisions log and a task list for the key result page, applied only after you accept it.
  • A topic, decision or gap can start a Workbench chat with the topic page, the last meetings and branch status attached.

How to test

In your own Workbench. First get the new code on screen: Settings → System → Restart Workbench, and when it is back, reload the tab once with ⌘+R.

  1. Version. Settings (the gear, top right) → Releases. “6 milestones so far. You’re on 0.6.0.” on one line, and v0.6.0 “Hand over and look closer” at the top, marked Current.
  2. Hand a chat over. In an idle chat click the agent chip under the message box, pick another agent that is ready, type “continue with the tests”, confirm. The thread shows “Handed over from Claude to Codex” (your agents’ names), and the new agent answers knowing what was done before. Check that the chat is still the same one in the sidebar.
  3. Browser extension. chrome://extensions → Developer mode → Load unpacked → the extension folder (or reload it if it is already there; it should say 0.2.0). Settings → System → Browser extension → Show pairing token, paste it in the extension’s options and press Test. Open your app on localhost, press Alt+Shift+P, click an element, type a note, press Enter. A chip with the file and line, and two screenshots, waits in the message box with your note. Then Alt+Shift+R, click around, press it again. One chip with the numbered steps and a storyboard picture.
  4. Show on the running page. With the extension connected, open the Changes panel and click the eye on a changed file. Your running page comes forward with the elements from that file outlined, and a count.
  5. Other servers. In a terminal: cd ~ && python3 -m http.server 8123. Open the right panel’s Server tab. “Other servers on this computer” lists :8123 with its command, folder and age. Click Stop twice: the row goes and the terminal command ends.
  6. Night shift “Only if this fails”. Sidebar → Night shift → new task, any folder, any text, “Only if this fails” = true, start it. The task finishes at once as “All clear”, with no agent started and no worktree left. With false instead, the agent starts and gets the output.
  7. Actions. ⌘+K → Show actions in a git project. The tab lists the one-click jobs your skills offer (auto-heal’s, for instance).
  8. Spanish suggestions. Send a short message in Spanish. The suggested replies under the answer are in Spanish. (Uses a little Claude usage.)
  9. Work Hub. Open the Work Hub tab. The home screen is Sync prep, with a row per person; the Topics screen has one card per topic; “Start a chat in Workbench” on a topic opens a chat with the topic page attached. It is empty until meetings are saved in the Inbox.
