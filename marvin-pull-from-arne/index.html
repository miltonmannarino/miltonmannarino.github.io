The short answer

  1. Merge, don't cherry-pick. Marvin is 755 new files plus hooks in 27 core files. Picking commits one by one would break at the first core hook.
  2. Arne first. A dry-run merge shows 24 conflicting files. 23 of them are between Arne's branch and development itself, because his branch is 186 commits behind. That is his to bring up to date, not Piotr's.
  3. Then one merge for Piotr with exactly one conflict of his own: vite.config.ts, where both branches add something to the same line. Easy.
  4. Review the wall generator after the merge before trusting "Create boundary walls" again. Three people have now changed it.
  5. The Go service is a separate repository (lumoagent, branch development_ai-chat). Nothing to pull; check it out next to platform.

How to do it, in order

Learning note: git merge brings a whole branch across and remembers it, so later merges only bring what is new. git cherry-pick copies single commits and forgets where they came from; it suits small, self-contained commits, not 31 commits with hooks in 27 core files.

Step 1 · Arne brings his branch up to date (once)

git checkout development_ai-chat
git fetch origin
git merge origin/development          # expect the 23 files above
# resolve, then:
pnpm install
pnpm typecheck
NODE_ENV=test pnpm exec vitest run src/lumocad/features/assistant
git push

Milton's branch then needs one line to follow: git merge origin/development_ai-chat on marvin/native-apply-milton (no conflicts expected: his seven commits only touch the Marvin folder and manuals/).

Step 2 · Piotr merges Marvin into the harness branch

git checkout lumocad/local-harness-piotr
git fetch origin
git merge origin/marvin/native-apply-milton   # Arne's branch plus Milton's 7 commits
# expect one conflict: vite.config.ts — keep the harness plugin AND Arne's define
pnpm install                                  # package.json gained scripts, no new dependencies expected
cp .env.dist .env.marvin-example              # copy the two new VITE_ lines into your .env
pnpm typecheck
NODE_ENV=test pnpm exec vitest run src/lumocad/features/assistant src/lumocad/lab
pnpm harness install-skill                    # the harness skill is gitignored; the Marvin AGENTS.md is not

If Arne cannot do step 1 soon, the same merge works today, but Piotr then resolves all 24 files himself, including the wall-generator ones, which he is the right person for anyway. Milton can pair on the machine files.

Step 3 · Run the service next to the harness

git clone git@github.com:Lumoview-Building-Analytics-GmbH/lumoagent.git
cd lumoagent && git checkout development_ai-chat
# MongoDB (Docker or local), env file with the key from Scaleway, then:
go run . serve --env-file ~/marvin.env         # port 8091; browser on 5173

The full checklist, including the MongoDB commands and the "Cannot connect to marvin" fixes, is in src/lumocad/features/assistant/AGENTS.md after the merge.

Step 4 · Review what changed for everyone

  • Wall generator (part D). Run "Create boundary walls" on three buildings with the merged code and with development, compare wall counts, thicknesses and the residual regions. Owner to agree: Piotr knows the generator, Arne made the change.
  • General fixes (part C). Open one small PR each against development so they stop travelling inside the Marvin branch.
  • Core hooks (part B). Agree that they are temporary: tool-map step 5 removes them as each Marvin tool moves onto the editor's own events (step 1 of that plan is done for room moves).
