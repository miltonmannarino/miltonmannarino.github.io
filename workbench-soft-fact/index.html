Soft-fact: done is proven, not claimed

A new checklist item that turns a chat into a small software factory. The agent writes a spec and its tests first. You sign them off in Workbench. From then on Workbench, not the agent, runs the signed-off checks after every answer. Done means every check passes on a commit and nothing locked was touched.

As of 31 October 2026: built in the working copy and tested, but not committed. Type check and all 164 tests pass. It was tried end to end in a private Workbench with the stand-in Claude, but not yet with a real model.

Why it exists

When an agent says “done, looks right”, nobody can check that claim without redoing the work. A measurement that runs the same way every time can be checked. Soft-fact moves the judging from the agent to Workbench.

The assembly line

Five stations. The colour shows who owns each one: the agent, you, or Workbench itself.

1

Sort

Agent

Decides the kind of task (feature, change, port, algorithm), its size, and what to compare against. It asks you only what it can’t find out.

2

Spec and tests

Agent

Writes the examples, rules and “not doing” list, then the tests and factory.json. It commits them and stops.

3

Sign-off

You, in Workbench

You see the exact commands and locked files. Workbench checks that the new tests fail first, then locks everything.

4

Build loop

Agent

Runs the receipt itself, fixes the biggest failure, keeps or reverts the change, and notes surprises in traps.md.

5

Receipt

Workbench

After every answer, it runs the signed-off checks and says whether the work is done, failing, uncommitted, or tampered with.

Stations 4 and 5 repeat until the receipt says Done. “Send to agent” hands the failures back.

Where the design came from

The OBJ→roof work on the platform improved fastest once an outside measurement replaced the agent’s own judgement. Four properties made that grader trustworthy, and Soft-fact builds each one in:

Roof grader propertyIn Soft-fact
Measured against realityThe reference is fixed before the code exists: examples you approve, old code for ports, or real data for algorithms.
Explained its errorsA grader check lists its biggest errors by cause. Failing tests show the end of their output.
Couldn’t be fooled by dropping thingsA score may not improve by leaving more out on purpose, and locked tests can’t be edited.
Cheap to runPlain commands with no browser required. They run after every answer, so they should stay fast.

It is opt-in per chat, not a default mode. Most work is new features, where no old code exists to compare against. There, the reference is the examples you approve before any code is written.

Words used here

Spec
A short file of concrete examples (“a run with 2 failed jobs → exactly one re-run request”), rules that always hold, and what won’t be done.
Sign-off
You approving the spec and checks in Workbench. It locks them and records exactly which commands may run.
Fails first
A new test must fail before the feature exists; otherwise it isn’t testing the new work. (Elsewhere this is called “red first”.)
Lock
A fingerprint (a hash) of each signed-off file. Any later change shows up.
Receipt
The result of running the signed-off checks: each check’s pass or fail, scores, locks, and a verdict.
Damage check
“Everything else still works as before”: usually the project’s existing tests and type check.
Grader
A check that prints a score instead of pass or fail, with errors broken down by cause, as the roof grader does.
Ratchet
A grader’s score may not get worse than the best committed score so far.
Held-back data
Cases kept in a folder outside the repository. Workbench runs them, but the agent never sees their output, which catches work tuned only to the visible cases.

A Soft-fact item in the Checks menu

The checklist menu (the list icon next to the paperclip) has a new built-in item, Soft-fact, off by default. Switched on, it tells the agent to follow the shared soft-fact skill and to stop for your sign-off instead of signing off itself.

Like the other checks, it can be part of a project’s defaults. It works the same for Claude and Codex.

The Soft-fact bar above the message box

While the item is on, a bar shows where the work stands. It changes as the chat moves along:

  • No spec yet: the agent writes one first.
  • Spec ready: it names the title, how many checks, and how many locked paths.
  • Signing off / checking: shown while Workbench runs commands.
  • Failing: how many checks fail, and which ones.
  • All pass, not committed: done only counts for a commit.
  • Done: every check passes on a named commit, and the locked files are unchanged.
  • Locked files changed: someone edited what was signed off.

Sign-off: you see the commands, then Workbench locks them

  • Review and sign off lists every command Workbench will run in this folder, which checks must fail first, the locked files, any held-back folder, and what isn’t measured.
  • Sign off and build refuses if the spec or tests aren’t committed, or if a test marked “fails first” already passes.
  • Workbench keeps the record, with each locked file’s fingerprint, in data/factory/<chat>/, outside the repository. A copy goes to .factory/<name>/signoff.json for the repository’s history. Editing that copy is flagged.
  • The agent is then sent “I signed off the soft-fact spec in Workbench. Build it now.”
  • When the checks or a locked file change later, Details offers Sign off again. Until then, Workbench keeps running the checks you signed off.

The receipt after every answer

After each answer that finished normally, Workbench runs the signed-off checks itself. Details shows each one:

  • Pass or fail, the exit code, the time, and the end of the output for failures.
  • Graders show their score, its limit and the best committed score. A grader fails if its score is over the limit, got worse than the best, or improved by leaving more out on purpose. The score history is kept with the record, outside the repository.
  • Held-back data is run too, but only its pass or fail and its score are kept, never its output.
  • Send to agent sends the failures and their output as your next message. Check again runs everything now.

Checks don’t run after a stopped or failed answer, or while a queued message goes out next, so they never test a folder the agent is still changing.

Auto-merge waits for a green receipt

A worktree chat set to Merge automatically no longer merges after every finished answer while Soft-fact is on. It merges once the receipt passes. Until then, the merge bar says why it didn’t merge: “Not merged: the soft-fact checks aren’t green yet.” The manual Merge into … button still works.

The skill agents follow, in any repository

skills/soft-fact/ is linked into ~/.claude/skills and ~/.codex/skills, like artifact-page, so it works in every repository, including the platform repository with the roof work.

  • SKILL.md: the phases, the files in .factory/<name>/, how to write examples, the grader output format, and the rules (never edit locked files, never write “looks good”, quote the receipt).
  • scripts/receipt.mjs: plain Node with no dependencies. plan checks factory.json, signoff locks and enforces fails-first, and run prints the receipt. The agent and Workbench run the same script, so they judge the same way.
  • A state.json keeps the phase between turns, since the method takes several turns.

Safety: only commands you signed off ever run

Workbench runs the checks itself, outside the agent’s permission prompts, so it is strict about what runs. Commands come from Workbench’s own record, not from factory.json, which the agent can edit. If the commands change, nothing new runs until you’ve seen them and signed off again. Like any test run, they execute the project’s code in the chat’s folder, as if you ran them yourself. The README’s security section says so.

How to test

In the real app first, then the automated checks that ran on 31 October 2026.

In Workbench

  1. Start a new chat in a repository. Open the Checks menu (the list icon next to the paperclip), switch on Soft-fact, and ask for a small feature. Expected: the bar reads “Soft-fact is on. The agent writes the spec and its checks in .factory/ first…”. The agent writes .factory/<name>/, commits, and stops.
  2. After its answer, the bar reads “Spec ready to sign off”. Click Review and sign off. Expected: every command, the “fails first” tags, the locked files and the not-measured list.
  3. Click Sign off and build. Expected: a short “Signing off…”, then your message “I signed off the soft-fact spec in Workbench. Build it now…” goes to the agent. After its answer, the bar shows Workbench’s receipt.
  4. If something fails, open Details, then try Send to agent. Expected: each failing check with its output, and the agent receiving them as one message.
  5. Once the agent commits a green build: Expected: “Done: N/N checks pass on <commit>, locked files unchanged.”
  6. To see the guard work, edit a locked test yourself (for example, make it always pass), commit, and click Check again. Expected: “Locked since sign-off, but changed: <file>”, never Done.
