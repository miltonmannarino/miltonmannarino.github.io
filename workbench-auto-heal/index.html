Auto-heal: a weekly check that only wakes an agent when something broke

Once a week, Workbench runs a computed health check on a repository: tests, types, a security audit, code complexity, and a check that the Claude and Codex command-line tools still behave the way Workbench reads them. If everything passes, nothing else happens and no model is used. If something fails, an agent gets the report, fixes only that, and leaves commits for you to merge in the morning.

As of 2 November 2026: built in the working copy and tested, not committed. Type check and all 250 tests pass. The new Night shift controls were tried in a private Workbench with the stand-in Claude. The contract check's live turns ran against the real Claude Code 2.1.312 and Codex 0.163.0 and passed. A real weekly run, with a real agent fixing something, hasn't happened yet.

How a week goes

The problem: when the Claude or Codex CLI changes the shape of its output, Workbench chats break, and you find out by using them. The same goes for a test that quietly started failing or a dependency with a new security advisory. Auto-heal looks once a week, cheaply, and only spends a model when there is something to fix.

Worktree
A second checkout of the same repository in its own folder (.worktrees/…), on its own branch. Night shift runs every task in a new one, so your own checkout is never touched.
fallow
A code analyser for TypeScript and JavaScript. It reports functions over complexity limits, unused files and exports, import cycles (A imports B, which imports A) and duplicated code.
CLI contract
The list of flags, event names and fields Workbench relies on when it drives the claude and codex tools, checked against the installed versions.
Security advisory
A published warning that a package version has a known vulnerability, with the version that fixes it. pnpm audit lists them.

What changed

Three pieces: a skill any repository can use, a contract check specific to Workbench, and two new options in Night shift that make it run weekly and cheaply.

The auto-heal skill

A skill is a folder of instructions and scripts that Claude Code and Codex load on request. This one lives in skills/auto-heal/ and is linked into ~/.claude/skills and ~/.codex/skills, so it works in every repository on this Mac.

  • The check (scripts/check.mjs) has no model call. It finds the package manager, installs packages when the folder has none, runs the repo’s own typecheck, lint and test scripts, then pnpm audit, pnpm outdated, fallow, and any extra checks listed in .auto-heal.json.
  • Exit code: 0 nothing to fix, 1 something to fix, 2 the check itself broke. The report is saved to .git/auto-heal/report.md, shared by all worktrees of the repo.
  • Trend, not just totals: fallow’s numbers are compared with the run from about a week ago, so “3 more import cycles than last week” stands out.
  • Pinned: fallow runs as fallow@3.38.1, so an unattended run never fetches whatever was published last night.
  • The rules (SKILL.md): fix only what is under “To fix”, in order: install, typecheck/lint/tests, the repo’s own checks, then security advisories of high severity or worse, upgraded within the same major version only. One commit per kind of fix. Never push, never edit the check to make it pass.

The Claude and Codex contract check

Workbench drives claude by reading its stream of JSON events, and codex through its app-server protocol. The unit tests use a stand-in Claude that prints the old shapes, so they stay green when a real CLI update renames something. scripts/cli-contract.mjs checks the real ones, in two layers:

  • Every run, free, about a second. claude --help must list every flag Workbench passes. Flags hidden from help are tried with no input: an unknown one fails at once, before any model call. Codex prints its own protocol as a JSON Schema (codex app-server generate-json-schema); every method, item type, status and field Workbench uses must be in it.
  • Only when a CLI version is new to it. One tiny real turn each (Haiku; the smallest Codex model on a temporary thread), and the events are checked against what server/claude.ts and server/codex.ts read. A few cents, about once per CLI update. A usage limit makes it a warning, tried again next week.
  • A guard test scans the server code: a new flag or Codex method there fails the tests until it is added to the contract, so the contract can’t fall behind.

It reuses Workbench’s own Codex config handling (server/codexConfig.ts). Without it, the live turn went to a local Ollama server set in the Codex config, and timed out.

Night shift: weekly tasks and “Only if this fails”

Night shift already ran queued requests one by one in new worktrees while you’re away. Two options make it a weekly, cheap scheduler:

  • Repeat: Every <day> with a time. The task stays under Every week; at that time it queues a copy of itself and starts the shift if it isn’t running. One missed while Workbench was off runs when Workbench starts again. Run now queues it at once; × stops it repeating.
  • Only if this fails: a command run first in the new worktree. If it passes, the agent isn’t started, the task says “All clear”, and the empty worktree goes. If it fails, its output goes to the agent with the request. Stop ends it mid-check.
  • The one-hour limit for an agent starts when the agent starts, not when the check does.

The agent fixes

Things that are broken, with a clear right answer.

  • Failed install, type errors, lint errors, failing tests (the code, not the test, unless the test is wrong, said why)
  • A failing repo check, such as the CLI contract: update the code to the new shape
  • Security advisories of high severity or worse, within the same major version; a major upgrade is reported instead

How to test

The running Workbench serves the last build, so it doesn’t show the new controls yet.

  1. Run pnpm build, then Restart Workbench.The Night shift panel’s add form now has “Only if this fails”, “Check afterwards” and a Repeat picker.
  2. Open Night shift (bottom of the sidebar, or ⌘K). Pick workbench, Claude, Auto.
  3. Write: “Use the auto-heal skill: fix what the check found, then report.”
  4. Set Only if this fails to node ~/.claude/skills/auto-heal/scripts/check.mjs.
  5. Pick Every Sunday and 03:00, then Add weekly.It appears under Every week with its next time.
  6. Click Run now.Today it should find the security advisories and start the agent with them as “What the check found”. On a week where the check passes, the task shows “All clear” in green and no chat is made.
  7. By hand, in any repo: node ~/.claude/skills/auto-heal/scripts/check.mjsPrints the report and exits 0 or 1. Add .auto-heal.json for repo-specific checks.
