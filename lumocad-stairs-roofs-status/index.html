LumoCad feature status · product view

Stairs and roofs are real features — with different kinds of unfinished work.

This is a plain-English read of what the application can do today, where the rough edges are, and why “missing” means something different inside LumoCad than it does when sending the model to Revit.

As of 3 November 2026Based on the platform source, feature manuals, tests and integration backlog

The short answer

Both features are well beyond a prototype in LumoCad. A user can create, edit, save, reopen, view and export stair and roof geometry. Roofs have the broader modelling vocabulary; stairs have the more mature “connect it safely to floors” workflow. The biggest delivery gap is not ordinary in-app modelling: it is faithful import into Revit.

Important distinction

The web app and its Revit extension are separate products. “Roof import is missing” means a roof made in LumoCad is not yet rebuilt faithfully by the Revit extension. It does not mean LumoCad cannot model roofs.

What works today

“Available” describes the LumoCad application itself.

Roofs

Flexible roof modelling, from familiar shapes to hand-shaped surfaces.

Start from a footprint Available

Draw a roof outline, trace suitable existing lines, or use the drone-model outline. The outline can be edited later and can snap to building geometry.

Use common roof forms Available

Flat, gable, hip, shed and Dutch-gable start as one-click forms. Saltbox and butterfly are available as editable surface forms; further reshape helpers cover forms such as mansard, gambrel, jerkinhead and M roofs.

Control real roof behaviour Available

Users can set overhangs, edge slopes, split a roof into regions, raise a region, join several roof segments, and control how they meet.

Add roof features Available

Skylights/openings, dormers, chimneys or equipment boxes, and parapets are modelled as roof-aware features rather than simple flat symbols.

Freeform work Available

Freeform roofs support differently high eaves, interior surface points and fold lines. The system also has drone-derived roof heights and mesh round-trip checks.

Stairs

Structured stair modelling with strong floor and opening coordination.

Place useful stair families Available

Straight, double-straight, quarter-, half-, two-quarter- and three-quarter-turn stairs are supported, as are equivalent winding variants. Custom sequences of turns can be reopened and edited.

Connect stairs to real floor slabs Available

The stair can attach between selected floor slabs, across several levels, or remain detached. Its start, end and rise are calculated from those selections and offsets.

Edit detailed geometry Available

Users can adjust width, tread/riser values, turn position and direction, landings, terminal landing alignment, construction style, and movement/snapping.

Keep floors and stairs consistent Available

Openings through affected slabs are created and updated with the stair in one save/undo operation. The system validates unsafe overlaps before saving.

See it in the right context Available

There are top-plan, dedicated stair-elevation and 3D views, plus IFC export. Plans distinguish the cut portion from the part above the viewing height.

What is still missing or needs care

Ordered by impact, not by implementation difficulty.

Cross-product · highest impact

Revit hand-off is incomplete

The extension currently has only partial stair support and no roof-import phase. Winding stairs, exact slab-based stair heights, terminal landings and complete validation still need work. Roof segments, joins, freeform surfaces and roof features have not yet been implemented for Revit import.

LumoCad · known product limit

Not every stair shape is offered

Spiral, curved and double-return stairs are not supported. “Custom turns” can preserve unusual combinations already made, but it is not offered as a fresh placement preset.

LumoCad · known product limit

One floor-update path remains unfinished

When a stair changes, its own generated slab openings are managed together with it. Refreshing space-boundary openings is explicitly not implemented yet, so that related boundary view can need separate attention.

LumoCad · interaction gap

Toolbar deletion for stairs is disabled

Selected stairs can be deleted from the sidebar or with Delete/Backspace. The toolbar’s delete control is currently disabled, which is an inconsistent route rather than missing deletion itself.

LumoCad · durability gap

Roof material layers are not a durable contract

A roof remembers its total assembly thickness and a type ID, but full material-layer detail is not guaranteed after reload. That limits reliable material/type mapping into another system.

Evidence · what has not been claimed

No blanket “production-complete” claim

The codebase contains focused tests for geometry, saving, loading, undo, plan output and many roof/stair interactions. This review did not run a live user acceptance session or a full Revit round-trip, so those outcomes remain unverified here.

Practical reading: for work inside LumoCad, roofs and stairs are usable authoring systems. For a workflow that depends on opening the same result in Revit, treat stairs as a controlled pilot and roofs as a planned integration delivery until the named Revit backlog items are completed.

How this was assessed

Evidence reviewed: the current LumoCad stair manual; current stair and roof source modules, tests and feature controls; source history through 30 October 2026; and the explicit Revit geometry-update backlog. “Available” means supported by the present source and documented workflow. “Missing” is limited to documented gaps; it is not a guess about future product priorities.
